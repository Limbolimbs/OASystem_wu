# 独立セキュリティ管理コンソール

通常の業務アプリとは別のJavaプロセスで起動する、ローカルHTTPS管理アプリです。
黒・青灰色の画面に、青緑の状態表示と監査テーブルを配置します。
業務アプリのメニュー、ロゴ、接続先URLを管理画面へ表示しません。
これは表示上の分離であり、「関連を追跡できない」ことを保証する仕組みではありません。

## 利用できる操作

### 個人認証と権限分離

最高管理者は本機のPowerShellで発行した既存ID・パスワード・認証器を使用します。
個人担当者の追加でこれらを共有又は再発行しません。担当者は業務アカウントとは別です。

| 操作 | 最高管理者 | 監視・運用 | 監視のみ |
| --- | --- | --- | --- |
| 状態・完全IP・監査参照 | 可 | 可 | 可 |
| 一般社員の新規認証保護、接続元15/60分制限 | 可 | 可 | 不可 |
| 保護/制限解除、接続元24時間制限、管理権限社員の保護 | 可 | 申請・最高管理者の審査 | 不可 |
| 担当者追加・氏名/権限変更・有効化・無効化・論理削除・再招待 | 可 | 不可 | 不可 |
| 本人のパスワード変更 | 本機保守設定 | 可 | 可 |
| 監査の編集・通常削除、社員情報更新、任意SQL/OSコマンド | 不可 | 不可 | 不可 |

本人の新パスワードは空白なし半角12～128文字、大文字・小文字・数字・記号のうち3種類以上です。
監視・運用担当者は最高管理者の既存長期制限を短い期限で上書きできません。制限短縮も審査対象です。
最高管理者の既存資格情報は本機の保守設定で保持し、Web画面から他の担当者が参照・変更できません。
新規TOTPは各人別の160bitランダム秘密鍵、30秒・6桁・SHA1です。6桁の偶然の一致はあり得ます。
個人別の採用区間を保存し、同じ区間の再使用を拒否します。最高管理者への自己提権は禁止です。

### このPCでの更新

コンソールを停止してビルド後、初回だけ次を実行します。

```powershell
.\scripts\enable-members.ps1
.\scripts\apply-members-schema.ps1
.\scripts\start.ps1
```

この作業で12のSQLと本機の個人認証鍵を適用済みの場合、再適用は不要です。起動のみ行います。
12は担当者の管理インスタンス・役割・認証世代・招待状態を追加し、専用試行制限と運用審査を追加します。
各管理インスタンスの最高管理者は担当者として変更できません。教員用は別の検証DB又は独立設定とし、
本機の秘密設定を配布しません。担当者認証鍵を紛失すると、その担当者は再招待による認証器再登録が必要です。

### 担当者の開通

1. 最高管理者が「セキュリティ担当者管理」で管理ID・氏名・操作範囲を登録し、理由と新TOTPで確認します。
2. 一回限り・24時間有効の招待URLを本人確認のうえ交付します。メール送信はありません。
3. 本人は最高管理者と別のブラウザプロファイル又はWindows利用者で招待URLを開きます。
4. 本人がパスワードを設定すると招待を消費します。登録中の会話は管理画面への認証として使えません。
5. 本人のGoogle AuthenticatorでQRをスキャンし、6桁コードで登録を確認します。登録は10分以内です。
6. 最高管理者が本人と操作範囲を確認し、担当者一覧の「有効化」を実行します。
7. 本人は自分の管理ID・パスワード・新しい認証器コードでログインします。

招待URLの秘密コードはフラグメントに置き、読込み時にURLから除去します。コードはPOSTで検証し、
DBにはハッシュだけ保存します。QRは本機で生成し、第三者のQRサービスやメールへ秘密鍵を送りません。
最高管理者が担当者のQRや秘密鍵を確認する機能はありません。登録画面・応答はno-storeです。
閉じた招待を再表示せず、紛失・期限切れ・途中の登録失敗は「再招待」で旧招待と旧認証器を撤回します。

無効化、論理削除、権限変更、再招待、本人パスワード変更で認証世代を変更し、旧会話の次要求を拒否します。
再有効化でも旧会話は復活しません。無効化前に確定した操作を自動取消するものではありません。
監視・運用担当者の高権限操作は「運用申請・審査」へ送ります。最高管理者は新TOTPと理由で承認又は却下します。
承認時に実操作と審査・監査を同じTXで確定し、監査障害・競合は全更新を取消します。

### 本機の権限境界

複数の担当者を作成しても待受は127.0.0.1のままです。他PCのlocalhostからは接続できません。
担当者へサービス実行用Windowsアカウント・DPAPI設定・DB資格情報・OS管理者権限を渡さないでください。
同じサービス実行者としてPowerShellへ入れる人に対し、画面の権限分離だけで秘密設定を保護できません。
複数PCからの利用は別途VPN/内網HTTPSとサービスアカウントのアクセス設計が必要です。公開トンネルは使用しません。

- 現在の認証制限、保護中識別子、直近24時間の認証拒否を確認する。
- 社員の新規パスワード認証を保護し、制限・失敗回数を解除する。
- 記録済み接続元識別子のログイン試行を15分・60分・24時間制限する、又は解除する。
- 共通監査ログと専用管理操作履歴を検索・ページ送りする。

保護は社員の削除、役割変更、パスワード再発行ではありません。保護時に認証世代を進め、既存セッションの次要求を拒否します。
解除時にも認証世代を進めるため、保護前のセッションは復活しません。再ログインが必要です。
接続元制限はログイン入口の制限です。全サイト通信を遮断するファイアウォールではありません。
IPのSHA-256識別子は内部の照合・制限用です。原始IPv4/IPv6と補助情報は別の暗号化証跡として保存し、
管理画面で完全なIPを復号表示します。ハッシュしかない旧記録を推測で埋めません。

### 接続元とアクセス詳細

「接続元制限」「監査ログ」「管理操作履歴」には完全なIPと同頁の「詳細」を表示します。
詳細には日時、IP形式・種別、接続元ポート、入力ログインID（未検証）、経路・方式、HTTP/TLS、
ブラウザ・OS・端末区分（User-Agent由来）、言語、相関ID、関連イベント・拒否理由分類を表示します。
パスワード・OTP・Cookie・Authorization・リクエスト本文全体・クエリは記録しません。
ログインIDだけはログイン入口の所定形式に限って収集し、端末情報は自己申告として扱います。

原始情報は毎回のAES-256-GCM鍵で暗号化し、その鍵を専用RSA-3072-OAEP（SHA-256/MGF1-SHA256）公開鍵で包みます。
相関IDをGCMの追加認証情報とし、別の要求への付け替えを検証で拒否します。
業務アプリは公開鍵のみ、秘密鍵は独立コンソールのDPAPI内です。暗号化を署名や外部監査の代替としません。
IP地域照会はコンソールに配置したDB-IP City/ASN Liteをオフラインで読み、訪問者IPを外部サービスへ送信しません。
国・地域・都市・代表座標・AS番号・AS組織・データ作成日を表示します。
地域・座標は推定で、住所・GPS・本人・契約回線を保証しません。私有・loopback・文書用IPは地域照会しません。
無料データはCC BY 4.0の表示条件に従い、結果ページにDB-IPへのリンクを置きます。

### 既存コンソールへの証跡追加

ビルド済みの`security-console`で次を順に実行します。現在の管理パスワード・TOTPは変更しません。

```powershell
.\scripts\enable-evidence.ps1
.\scripts\apply-evidence-schema.ps1
.\scripts\update-geodata.ps1
```

11のSQLで`security_access_evidence`（追記証跡）と`security_source_profile`（最新証跡参照）を追加します。
限定コンソールDBユーザーには証跡SELECT/INSERT、プロファイルSELECTだけを追加します。
業務アプリとコンソールを再起動すると新規イベントから収集します。
すでに適用したこのPCでは再適用不要です。生徒PCで作成した秘密鍵を教師用GitHubへ登録しません。

業務アプリの公開鍵既定値は`D:\oa-maintenance\control-public\evidence-public.pem`です。
別の配置では`oa.security.evidence-public-key`（又は設定例の`OA_EVIDENCE_PUBLIC_KEY`）を設定します。
秘密鍵を失うと既存証跡を復号できません。DPAPIバックアップは同じWindows利用者の保守領域に保持します。
証跡用秘密鍵は`CONTROL_EVIDENCE_PRIVATE_KEY`として起動プロセスにだけ渡します。

公開地域データは`D:\oa-maintenance\geoip`へ置きます。更新スクリプトは公式ダウンロードと公開チェックサムを確認し、
新しいデータを配置します。再起動で読込みます。MavenやDBで訪問者情報を第三者へ送る機能ではありません。
証跡の保管期間・容量制限・鍵交換/紛失回復・バックアップ運用は本番導入前に定めてください。

## 認証と境界

| 項目 | 動作 |
| --- | --- |
| 待受 | `127.0.0.1:9443`、HTTPSのみ。リクエストもloopbackを確認 |
| 認証 | 専用管理ID＋Argon2idパスワード＋時刻ベース認証器（TOTP） |
| コード | 30秒・6桁・SHA1、隣接1区間まで許容。同じ区間の再使用をDBで拒否 |
| 変更確認 | 理由1～300文字＋新しい認証コード。直前のログインコードは再使用不可 |
| 試行制限 | 観測24時間、累計5回で15分、10回で60分、15回で手動解除が必要な認証保護 |
| セッション | 無操作10分、認証後最大1時間。自動GETでは延長しない |
| Cookie | `__Host-CONTROL_SESSION`、Secure・HttpOnly・SameSite=Strict |
| 更新要求 | 全POSTに独立したセッションCSRFを要求 |
| 通信表示 | jQuery CDN＋`$.ajax`、独自確認ダイアログ、同一画面を部分更新 |
| 変更記録 | 保護・解除と管理操作監査を同一トランザクションで確定 |

OTPの失敗回数・消費済み区間は認証専用トランザクションで保存します。
認証後に対象操作が競合・失敗しても、使ったコードは消費済みです。次のコードで確認してください。
障害時は変更を自動再送しません。通信切断などで確定結果が分からない場合は、一覧と履歴を再取得してください。
通常のOA管理者・総務担当のCookieでは、このアプリへ入れません。
`X-Forwarded-For`等の自己申告ヘッダーを信頼しません。ポート転送や公開トンネルも使用しないでください。

### 段階的な認証制限と解除

ログインと重要操作のTOTP失敗を、本人の同一累計へ加算します。制限中の要求では加算・期限延長を行いません。
15分・60分の満了だけでは段階を戻しません。完全ログイン成功又は24時間の観測期限で通常累計を清算しますが、
観測期限で有効な制限を短縮せず、15回で開始した保護を解除しません。操作TOTPの成功だけでは通常累計を清算しません。
未知IDの入力は最高管理者の失敗へ付け替えず、短時間の接続元制限を別に適用します。
業務の接続元60要求/分は総要求の頻度制限であり、パスワード失敗60回を許可する設定ではありません。

担当者の認証制限・保護は最高管理者が担当者管理の専用ボタンで解除します。理由と新しいTOTPを要求し、
解除・世代変更・監査を同じトランザクションで確定します。無効担当者を有効化したり、資格情報を変更したりしません。
最高管理者本人は担当者のWeb解除対象にできません。本人のWindows保守端末で次を実行します。

```powershell
.\scripts\release-owner-protection.ps1
```

この操作には同一Windows利用者のDPAPI設定、現在のパスワード、新しいTOTP、解除理由、明示確認が必要です。
資格情報を再発行せず、全ての旧セッションを失効させます。認証器を紛失した場合の復旧として使用できません。
パスワード・TOTP・DPAPI設定をコマンド引数やログへ記載しないでください。

スキーマ13を適用してから新しいアプリを起動します。既存資格情報・有効状態を保持する追加列だけの移行です。
業務側の `scripts/security/progressive-protection-schema.ps1` が適用済みなら、再適用は不要です。
観測期間・閾値・時間はOAの `oa.security.*` と管理側の `CONTROL_*` 設定で個別に設定できます。
閾値の順序、期間の正値を起動時に検証します。通常運用で制限回避のために値を変更しないでください。

## ビルド

Windows、Java 25、Maven 3.9以降を使用します。
リポジトリ全体を取得してください。SQL資源は親ディレクトリからビルドに取り込みます。
Eclipseでは、このディレクトリの`pom.xml`を別のMavenプロジェクトとして読み込みます。
OA本体の起動・ビルドだけでは、コンソールは起動しません。

```powershell
Set-Location D:\eclipse-workspace\OASystem\security-console
& 'D:\oa-maintenance\build-cache\apache-maven-3.9.16\bin\mvn.cmd' '-Dmaven.repo.local=D:\oa-maintenance\build-cache\repository' package
```

ビルド前に、起動中のコンソールを`Ctrl+C`で停止してください。Windowsでは使用中のjarを更新できません。
新たに配置するJDK、Maven、依存キャッシュもDドライブを使用します。
`-JavaExecutable`で別の既存Java 25を指定できます。初期化には同じJDKの`keytool.exe`も必要です。

## 初回だけ行う初期化

1. OAを停止し、クラウドDBをバックアップします。08・09のSQL適用後であることを確認します。
2. 接続情報を含む非公開`application.properties`を用意します。対象はAivenの`oa_system`です。
3. DB管理権限を持つ設定で、次の初期化を1回実行します。

```powershell
.\scripts\initialize.ps1 -SourceConfig 'D:\eclipse-workspace\OASystem\src\main\resources\application.properties'
```

初期化は`../src/main/resources/database/10_security_console.sql`を適用し、専用の限定DBユーザーを作成します。
新しいPCの初期化では、次の追加設定も必要です。11と12のSQLを適用してから初回起動します。

```powershell
.\scripts\enable-evidence.ps1
.\scripts\apply-evidence-schema.ps1
.\scripts\update-geodata.ps1
.\scripts\enable-members.ps1
.\scripts\apply-members-schema.ps1
```

既存社員データの一致を検証し、適用前DDLと移行記録を`D:\oa-maintenance\control-schema-*`へ保存します。
DDLは自動コミットです。失敗時は記録と適用済み構造を確認してください。表を削除してやり直しません。
移行途中で専用DBユーザーが作成済みになる場合があります。DB管理者が記録を照合してください。

限定ユーザーは社員のID・ログインID・役割・有効状態の参照、認証制限の変更、共通監査の参照、
専用認証状態の変更と専用監査の追加だけを許可されます。
社員パスワードの参照、社員更新、監査更新・削除、DDL権限は付与しません。
OA本体が利用するDBユーザーの権限まで変更する初期化ではありません。

`D:\oa-maintenance\control-private`にはWindows DPAPI（現在の利用者）で暗号化した設定とPKCS12証明書を保存します。
現在のWindows利用者、SYSTEM、ローカル管理者だけにディレクトリ権限を付与します。
既存ディレクトリを上書きしないため、同じ初期化を繰り返さないでください。
初期化済みのこのPCでは、次の登録・起動手順から進めます。

## 認証器の登録と起動

他人に見られない本機のターミナルで実行します。

```powershell
.\scripts\show-enrollment.ps1
```

表示される管理ID・初期パスワードを個人のパスワード管理ツールへ保管し、登録キーをTOTP認証器へ登録します。
時刻ベース、SHA1、30秒、6桁を選択し、PCと認証器の時刻を同期してください。
この表示をチャット、画面録画、GitHub、設計書へ貼り付けないでください。
登録キーは認証器の秘密鍵です。初期パスワードも変更用・回復用機能が整うまで厳格に保管してください。

```powershell
.\scripts\start.ps1
```

ブラウザで`https://localhost:9443/`を開き、専用管理ID・パスワード・認証コードでログインします。
既定ポートは9443です。別ポートを明示した場合はブラウザ側のURLも一致させてください。
本機専用の自己署名証明書のため、初回は証明書警告が出ます。
`show-certificate.ps1`のSHA-256指紋・有効期間と、ブラウザが表示する証明書を照合してください。
照合できない証明書を信頼しないでください。証明書の信頼ストアへ自動登録する処理はありません。
全ブラウザの証明書検証を無効にしたり、アプリをHTTPへ変更したりしないでください。
停止は起動したターミナルで`Ctrl+C`です。

Windows PowerShellで「スクリプトの実行が無効」と表示される場合は、内容を確認したこのローカルスクリプトだけを、
次の一時プロセスで実行できます。システムや現在の利用者の恒久的な実行ポリシーは変更しません。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\show-enrollment.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

不明なサイトから取得したスクリプトを、この方法で実行しないでください。

## 教員のPCでの確認

教員もリポジトリ全体を取得し、本人のPCでビルド・初期化して、このアプリをローカル起動できます。
生徒PCの`localhost`が教員PCから見えるわけではありません。生徒PCを公開する必要もありません。
接続設定は提出用・検証用DBに限定し、認可されたDB管理者が初期化します。
本番のDB管理パスワードを配布しないでください。自分のDPAPIファイルは別のWindows利用者へコピーしても復号できません。
各PCで専用管理ID内部キー・パスワード・認証器を発行し、共有しないでください。
管理画面だけが本機であり、業務DBをローカルへ移行する構成ではありません。

- `templates/access.html`、`templates/console.html`：日本語HTML

- `static/js/access.js`、`console.js`、`request-security.js`：認証・管理操作・通信保護
- `../src/main/resources/database/10_security_console.sql`：追加SQL
- `scripts`：初期化、認証器情報確認、証明書確認、起動

通常の`mvn test`は実DBを変更しません。
旧クラウド向け試験は`IsolatedControlStorageTest`、`IsolatedMembersStorageTest`、`IsolatedSessionsStorageTest`へ移行しました。

本番DPAPI・DB資格情報・実運用の復号鍵を試験へ読み込みません。`CONTROL_INTEGRATION_TEST`は使用しません。
社員パスワード参照・社員更新・監査上書きの拒否も隔離環境で検証しますが、本番DBユーザーの権限確認を代替しません。
既存の地域DBがある場合は`CONTROL_GEO_TEST=true`でオフライン照会を検証できます。

## 運用導入に向けた別要件

5/10/15回の段階制限・観察周期・会話管理は本実装に含みます。
メール通知、最高管理者のWebパスワード変更・高度な回復、複数最高管理者の相互承認、
監査保管期間・外部改ざん耐性は、別途仕様を定めます。
DB接続には、確認したAiven CAを格納した専用トラストストアと`VERIFY_IDENTITY`を使用します。
DB権限・ネットワーク制限・配布先のCA配置は環境ごとに確認します。ローカルHTTPS証明書の警告とDBのTLSは別の検証です。
独立プロセスでも、同じPCやDBの管理権限を侵害された場合の完全な分離は保証しません。
本実装を商用安全性・第三者レビュー済みの証明として扱わないでください。
