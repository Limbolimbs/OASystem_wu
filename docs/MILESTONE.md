# 段階成果：業務管理と共通セキュリティ

対象日：2026年10月17日

## 提出対象

OA業務アプリケーションと、別プロセスのローカルHTTPSセキュリティ管理コンソールを対象とする。
独立管理コンソールの管理者資格情報、DPAPI設定、認証器、私的証明書及び実業務データは含めない。
既存のExcel詳細設計書は別冊として扱い、ソースコードに混在させない。

## 業務の範囲

| 業務 | 提供する処理 |
| --- | --- |
| 認証 | 社員番号・既存ログインID、Argon2id、共通CSRF、会話期限、段階的ログイン制限 |
| 従業員・部署 | 検索、登録、所属・役割更新、有効化・論理無効化、部署の利用設定 |
| 営業 | 月次×部署の入力・編集、同時編集制御、ダッシュボードへの集計反映 |
| 勤怠 | 出退勤・休憩、履歴、外勤・在宅・休暇・休日出勤・残業・打刻修正と審査 |
| 勤務設定 | 勤務ルール、個別勤務予定、会社休日 |
| 公告 | 作成・編集・公開・下書き・検索・論理無効化・復元・本人既読 |
| 本人情報 | 会社管理情報の参照、現在のパスワードを確認した本人パスワード変更 |
| 独立管理 | 個別TOTP、担当者管理、運用申請・審査、認証保護、接続元情報、監査・会話管理 |

## OAの権限境界

| 処理 | 管理者 | 総務担当 | 一般社員 |
| --- | --- | --- | --- |
| 経営ダッシュボード | 可 | 不可 | 不可 |
| 従業員・部署の管理 | 可 | 不可 | 不可 |
| 全員の勤怠参照・他者申請の審査 | 可 | 可 | 不可 |
| 自分の打刻・本人情報・公開公告 | 可 | 可 | 可 |
| 新規勤怠申請 | 不可 | 不可 | 本人分のみ |
| 勤務ルール・個別予定・会社休日の管理 | 可 | 不可 | 不可 |
| 公告の作成・編集・公開設定 | 可 | 可 | 不可 |
| 営業実績 | 全部署 | 所属部署で営業利用が許可された場合のみ | 同左 |

審査担当者は本人の申請を自己承認できない。営業利用は役割名だけではなく、現在の所属・部署状態・利用許可で決める。
画面の非表示だけに依存せず、サーバー側で再判定する。独立管理のOWNER／OPERATOR／OBSERVERはOAの役割と別体系である。

## 検証と制約

検証は合成アカウント・専用MySQLの業務回帰、ブラウザーのAJAX動作、管理用限定DB権限、クラウド読取専用確認に分ける。
提出時の試験結果は別紙「検証結果」を参照する。実環境での本人認証を、隔離試験の合格だけで検証済みと扱わない。

商用運用の認定、未知の脆弱性ゼロ、法令・就業規則の適合、負荷・災害復旧、第三者の侵入試験は対象外である。
外部公開時の正式なHTTPS運用、DB最小権限、復旧・保管運用等は導入環境に応じた別の審査を要する。
給与、休暇残数、ファイルアップロード、営業実績ファイル取込、メール通知は本段階の提供範囲に含めない。
