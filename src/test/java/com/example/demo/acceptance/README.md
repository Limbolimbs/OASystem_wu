# 隔離受入試験

対象はOAの実サービス・実認証フィルターと、独立管理コンソールの役割・認証器・保護・会話・審査処理。
通常の `mvn test` では本ディレクトリーのDB試験を実行しない。

## 接続の固定と安全条件

- 専用MySQL：`127.0.0.1:13316`、DB：`oa_qa_20261015`。
- データ領域：`D:/oa-maintenance/business-acceptance-20261015/mysql-data/`。
- 本番設定・クラウド接続先を入力値として受け付けない。接続後も実ポート・データ領域・DB名・テスト識別行を確認する。
- DBのrootと社員パスワードは隔離試験専用値。実社員、最高管理者、実認証器の情報を利用しない。
- 各ケースで隔離データを初期化する。実DB・業務DBに対して実行しない。
- 打刻の基本fixtureは週7日の試験規則とし、実行日の曜日で通信試験が変わらないようにする。休息日・会社休日は各ケースで明示し、承認前後を検証する。本番の勤務規則は変更しない。
- スキーマ初期化は `OA_ACCEPTANCE_BOOTSTRAP=true` の別スイッチが必要で、空でないDBでは拒否する。
- 旧クラウド向けOA試験20件は `Isolated*IntegrationTest` / `IsolatedProgressiveLoginTest` へ移し、同じ専用DB・識別行ガードを適用した。実行指定は `OA_ACCEPTANCE_TEST=true` のみ。
- `OA_INTEGRATION_TEST` / `OA_EVIDENCE_INTEGRATION_TEST` / `OA_PROGRESSIVE_TEST` / `CONTROL_INTEGRATION_TEST` は有効にしない。実社員のパスワード移行バックアップや実運用の証跡復号鍵も読み込まない。
- 証跡検証の秘密鍵はプロセス内だけで生成・保持する。試験公開鍵だけをDドライブの保守領域へ保存する。

## 実行

ローカル受入環境のMySQLを確認し、PowerShellで `OA_ACCEPTANCE_TEST=true` を設定する。
Mavenの出力先は起動中の `target` と分離したDドライブのディレクトリーを指定する。
OAプロジェクトと `security-console` を順番にテストする。fixture初期化があるため、両プロジェクトのDB試験を同時に実行しない。
OAだけを検証する依頼では `security-console` は実行しない。

`OA_BROWSER_ACCEPTANCE=true` を追加すると、JUnitが起動する一時ポートの実OAサーバーにEdgeのヘッドレスブラウザーで接続する。
この試験はログイン、ロール境界、出退勤・休憩、新規申請・審査、営業実績・ダッシュボード連携、公告・既読を画面から確認する。
社員と営業部、最高管理者・運用担当・監視担当の権限を混同しない。
ブラウザー試験は同梱Node及びPlaywrightを再利用し、依存関係を新規インストールしない。

## 試験の限界

ローカルMySQL 8.0.45でJPA定義と実セキュリティSQLから構築した専用DBを使用する。
クラウドMySQLの版・実際の接続制限・限定DBユーザーの権限・実運用データ分布まで同一であることは保証しない。
この試験結果は侵入試験・全構成の負荷試験・商用運用承認を代替しない。
テスト完了後は専用MySQLだけを正常終了し、起動中のOAと管理コンソールは承認なしで再起動しない。
